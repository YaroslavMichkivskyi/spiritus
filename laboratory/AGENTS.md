# laboratory — Spiritus's own development

Where Spiritus is improved: to-do lists, ideas to think over, experiments
with its structure. Not a life area (that's `domains/`) — this is about
Spiritus itself. Tracked in git (drafts too), except `*.local.*` files.

## Index

| File | What |
|---|---|
| `improvements-to-do.md` | planned improvements to Spiritus, **in the order they will be done**; done items are removed |
| `drafts/` | half-built agents / spells / playbooks not ready to be wired in — one folder per draft, listed below |

## Drafts — `drafts/<name>/`

| Draft | What | State |
|---|---|---|
| `deployment/` | plan for easy setup: bootstrap, doctor, `setup` / `mcp-setup` spells, MCP catalog, `docs/`, README (`plan.md`) | being implemented |

A draft is **not** part of Spiritus: never follow, summon or cast it unless I
ask to work on it. Promoting one → `playbooks/self-update.md`.

## Rules

- Read only when I ask about plans / ideas or when changing Spiritus
  (`playbooks/self-update.md`) — not on every session.
- Format: Markdown — numbered list where order matters, bullets otherwise;
  one item = one entry, a `->` sub-line for Spiritus's clarifying notes.
- An item is done → remove it from its list and mention it in the change report.
- Notes may be in any language; this index stays in English.
- Added / renamed / removed a file or draft → update the index above.
